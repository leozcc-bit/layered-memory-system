> 只放**不随工作线数量增长**的内容；一切"活跃事项 / 进度 / 待办"放 STATUS.md。

- （项目一句话背景，恒定内容，写一次很少动）

## 二、通用规则
- （跨工作线稳定执行的行为规则；每条立规矩前过「纪律三问」：谁检查 / 怎么检查 / 失败会怎样）

## 三、场景对照表（找东西先看这里）

> 本表是「场景 → 去哪读」的**唯一入口**。任何内容移出本文件、或细节层文件改名，
> 必须当场更新本表。引用记忆位置时指向本表，不写具体文件名与节号——位置型引用一定会断，
> 且断链不报错。
>
> 本表按**内容类别**分行、不按工作线分行，因此不随工作线数量增长（归入规则层的判定不变）。

| 场景（要做什么 / 找什么） | 去哪读 |
|---|---|
| 看活跃事项、工作线进度与卡点 | `STATUS.md`（接活必读） |
| 查已定案事实（按 ID） | `DATA.md`——引用必须带 ID，无 ID 视为未载入 |
| 查某条线的过程与经验沉淀 | `notes/`（具体文件见 `STATUS.md` 对应行的「细节」字段） |
| 回溯旧版本 | `history/` |

## 四、体系规则
- 载入序列：MEMORY → STATUS → DATA → 校验三处签名 → 最近日志连续性 → 报告自检
- 三锚点：开工回显事实清单；变更当场记入数据层的待同步区；收尾逐条核销
  （收尾完成 ⇔ 日志已追加 ∧ 待同步清零 ∧ 产物已改 ∧ 快照已备）
- 快照：写 MEMORY / DATA / STATUS 前 cp 旧版到 `history/`，命名 `{主体}_vX.Y_说明.md`，
  版本号必须在第二段（写成 `MEMORY_改规则前_v1.1.md`，回退检测不比对它，巡检 D 组会报 WARN）
- 写前版本比对：签名版本 ≠ 本会话读到的 → 先重读再写
- 变更接口兼容检查：动手前先列接入点（谁读 / 谁检测 / 谁引用），逐个验格式与路径；
  列不出接入点就先别改。涉及内容外置或改名时，下游引用只指向「场景 → 去哪读」对照表
- 规则三问：答不出「谁检查 / 怎么检查 / 失败会怎样」的规则不落盘
  （动作纪律类例外：规定人做什么、而非机器查什么的，按「有可查的后验锚点 + 至少一次实发事故」衡量）
